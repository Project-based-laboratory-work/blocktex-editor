# image_layout — 画像のレイアウト解析（座標AI）

画像から、**ブロックの四角（座標）とラベル**を直接出す。OCR は文字しか見つけないので、ルールベース側
（EasyOCR → 段落まとめ → [image_rule_based](../image_rule_based/README.md)）は表・図の位置を出せず、
段落の区切り方も OCR の段落まとめに任せている。ここでは、それを画像から AI で決める。

```
画像 ─ image_layout（ここ）─→ ブロックの四角とラベル ─（四角の中の文字は OCR の結果から入れる）─→ ラベル付きIR
```

## しくみ

画像の各画素を「背景・見出し・段落・表・図…」の13種類に塗り分ける（セマンティックセグメンテーション）。

1. 画像を 768×576 に縮めて U-Net に入れる（[model.py](model.py)）。縮めながら広い範囲（段組み・表の形）を見て、
   広げ直しながら細かい位置（ブロックの端）を取り戻す。出力は 1/4 の 192×144
2. 正解は、正解の四角を **1画素ずつ内側に縮めて**塗ったもの。隣り合うブロックの間にすき間ができ、
   つながった画素のかたまり＝1つのブロックとして取り出せる（[dataset.py](dataset.py)）
3. 縮めて空いた外周（**ブロックのふち**）も、別の出力として当てさせる。推論では、ふちと判定した画素を消してから
   かたまりに分ける。こうしないと、上下に接した段落の間の1〜2画素のすき間を塗りつぶして、2つの段落が1つにつながる
4. それでも、ふちが1画素途切れていると、そこから隣の段落へつながってしまう。横幅9画素未満の細い部分を消す
   「開く」処理（モルフォロジーのオープニング）で、その細い橋を切る
5. かたまりを四角にし、縮めた分だけ広げて元の画像の座標に戻す（[postprocess.py](postprocess.py)）

## 使い方

`ai/` で実行する。学習データは [image_classifier](../image_classifier/README.md) と同じもの（image_dataset で自動生成）を使う。

```bash
python -m image_layout.train                                   # → checkpoints/unet/best.pt（計算機サーバのGPUで約70分）
python -m image_layout.train --no-boundary --out image_layout/checkpoints/unet_noboundary   # ふちを使わない版
# ルールベース側と比べる（ルールベース側のOCR結果 <dir>/ocr/ は image_classifier/run_ocr.py で作る）
python -m image_layout.evaluate image_classifier/data/val --checkpoint image_layout/checkpoints/unet/best.pt
python -m pytest image_layout/tests
```

`data/` と `checkpoints/` は git の管理外。

## 結果（検証 854枚、チーム共通の物差し evaluation/metrics.py）

image_dataset の今の既定（ビューアの背景付きのスクショを含む、#45 以降）で作ったデータで学習・採点したもの。

| | 検出 F1 | 適合率 | 再現率 | label_acc | 時間/枚 |
|---|---|---|---|---|---|
| ルールベース（EasyOCR → 段落まとめ → image_rule_based） | 0.541 | 0.473 | 0.633 | 0.653 | 0.2 ms ＋ OCR |
| **座標AI** | **0.843** | **0.884** | **0.807** | **0.998** | 297 ms（CPU） |

ラベルごとの検出の再現率（正解のブロックを IoU 0.5 以上で見つけられた割合）:

| | 表 | 図 | コード | 数式 | 箇条書き | 見出し | キャプション | 段落 |
|---|---|---|---|---|---|---|---|---|
| ルールベース | 0.436 | 0.000 | 0.161 | 0.597 | 0.487 | 0.875 | **0.976** | **0.832** |
| 座標AI | **0.979** | **0.972** | **0.933** | **0.824** | **0.855** | **0.941** | 0.935 | 0.796 |

ビューアの背景への強さ（検出 F1）: 背景の無いデータで学習したモデルは、背景付きのスクショで 0.554 まで落ちた。
今のデータで学習し直すと 0.835（背景の無い clean 0.844・スクショ 0.854 とほぼ同じ）。前のデータでの成績（0.848）も落ちていない。

工夫ごとの効果（検出 F1。#45 より前のデータで比べたもの）:

| | 後処理の「開く」なし | あり |
|---|---|---|
| ふちの出力なし | 0.768 | 0.843 |
| ふちの出力あり | 0.771 | **0.846** |

- 効いたのは「開く」処理（ふちの途切れから隣の段落へ漏れた細い橋を切る）。ふちの出力の効果は小さい
- 弱いところ: 段落（上下の段落がまだくっつく）、キャプション、その他（ページ番号。正解の段落の四角に入っていることがあり、
  正解をそのまま塗っても 2.5% しか見つからない）
- 注意: 学習も検証も image_dataset が作った画像なので、AIに有利な条件。人が正解を付けた本物の画像での確認はこれから
