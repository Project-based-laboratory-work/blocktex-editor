# 入力の制約（画像読み込み・PDF読み込み）と評価の方法

読み込みのパイプラインは2つある。どちらも出力は同じ共通JSON（[common/](common/README.md)）で、エディタで直せる形に戻す。
**入力の制約は、パイプラインごとに別に決める。出力は、どちらもエディタの機能の範囲に固定する。**

| | 画像読み込み | PDF読み込み |
|---|---|---|
| 入力 | PDFを画像にしたもの・スクリーンショット | TeX で作った PDF（文字の層があるもの）。**許可リストの範囲で割と自由** |
| 制約の考え方 | 作り方を固定する（見た目の幅を絞る） | 見た目は広げ、出力の要素は固定する |
| 状態 | 決定（第2回中間発表） | 許可リストで決定（2026-11-16）。チームに共有する |

## 共通: 出力の要素（両方のパイプラインで固定）

エディタの機能は広げない。出力は今の共通JSONの要素だけにする。入力にこの表で表せないものがあれば、近い要素に落とすか捨てる。

| 要素 | 復元できる範囲（ai/common） |
|---|---|
| タイトル | タイトル・著者・日付 |
| 見出し | レベル1〜3（番号が無ければ文字サイズの順） |
| 段落 | 文字＋太字・斜体・下線 |
| 箇条書き | 行頭の `•` `-` `1.` `(1)` などで項目を分ける |
| 数式 | 別行立て。数式OCRで LaTeX に |
| 表 | セル・列の揃え（左/中央/右）・キャプション |
| 図 | 位置・幅・キャプション（画像は選び直す） |
| コード | 行と字下げを保つ |
| その他 | ページ番号・ヘッダー（捨てる） |

文書の設定（用紙・文字の大きさ・1段/2段組・余白）は、エディタの文書設定（[web/src/model.ts](../web/src/model.ts) の `DocumentSettings`）にある。

エディタにはあるが、共通JSONにまだ要素が無いもの: 引用（quote ブロック）、脚注（文の中の `\footnote`）、目次、改ページ、リンク。
読み込みでは今のところ、引用は段落に、目次は「その他」に落とし、リンクは捨てる。脚注は対象外。
エディタは広げずに、共通JSONに要素を足すだけで戻せるので、必要になったらチームで決める。

正解ラベルはどちらのパイプラインでも、TeX の各ブロックの始まりと終わりに目印（`\special{pdf:dest}`）を埋め込み、
PDF上の位置から人手なしで付ける（[evaluation/README.md](evaluation/README.md)）。

## 画像読み込みの制約（決定）

元の文書の作り方を固定する。画像では書体の名前などの手がかりが消えるので、見た目の幅を絞る方が読み取りやすい。

| 項目 | 制約 |
|---|---|
| コンパイル | uplatex → dvipdfmx |
| 文書クラス | jsarticle / bxjsarticle（横書き） |
| 用紙・組版 | A4・10/11/12pt・1段/2段組 |
| パッケージ | amsmath・booktabs・listings |
| 書き方 | 見出しは `\section`〜`\subsubsection`、箇条書きは itemize / enumerate、数式は `align*`、表は tabular（booktabs）、図は figure、コードは verbatim / lstlisting |
| フォント | 明朝/ゴシックの入れ替えあり。埋め込みは IPAex・原ノ味 など |
| 言語 | 日本語・英語 |
| 画像の作り方 | PDFを画像にしたもの・PDFビューアのスクリーンショット（一部の切り出し・ダークモード・背景色・縮小・JPEGの劣化を含む。[image_dataset](image_dataset/README.md) の `screenshot`） |

**対象外:** スマホで撮った写真、文字色（白黒が前提）、上の表以外のパッケージ（TikZ など）、縦書き

## PDF読み込みの制約（2026-11-16）

### 変える理由

画像読み込みと同じ制約だと、PDF読み込みではルールベースが圧倒的に有利になる。

- PDFの文字には、書体の名前・大きさ・位置が正確に入っている。作り方を固定すると、手がかりがほぼ決まった値になる。
  例えば「書体が `CMTT` ならコード」「本文の1.2倍で太字なら見出し」のように、ルールが制約を逆からたどるだけで当たる
- 実際に、この制約で作った評価用データセット（synth_all）では、ラベル正解率がルールも自作AIも 1.000 で並んだ。
  差が出たのは、見た目をばらつかせたデータセット（hybrid_varied）だけだった（ブロックの検出F1: ルール 0.881 → AI 0.986）
- 一方で、実際のレポートは制約の外の書き方をよく使う。授業のレポート4本では、`\usepackage[T1]{fontenc}` のせいで
  コードの書体が `SFTT` になり、書体の名前で等幅を判定するルールが崩れた

### 考え方

- **入力は割と自由にする。ただし許可リスト方式。** 使ってよいエンジン・文書クラス・パッケージ・書き方を下の表に名前で並べ、
  **表に無いものは対象外**にする。評価用データを作るときに「何を混ぜればよいか」がはっきりし、範囲が勝手に広がらないため
- **出力の要素は固定する。** エディタは広げない。今の要素で表せないものは、近い要素に落とす（情報の一部は捨てる）。
  落とし方は表の「出力での扱い」の列
- **対応は一度に広げない。** 表の「段階」の順に、評価用データセットを作り直してルールと自作AIの差を測ってから次に進む。
  どの変更でどれだけ崩れたかが分かるようにするため

### 許可リスト（決定、2026-11-16）

| 区分 | 許可するもの | 段階 | 出力での扱い |
|---|---|---|---|
| エンジン | uplatex / platex（＋dvipdfmx）、pdflatex、lualatex | 2 | — |
| 文書クラス | jsarticle、bxjsarticle、jlreq（article 相当）、ltjsarticle、article | 2 | — |
| 用紙・組版 | A4・A5・B5・レター、縦/横、9〜14pt、1段/2段組（`twocolumn`）、余白（geometry） | 2 | エディタの文書設定にある範囲 |
| 本文・見出し・コードの書体 | 和文: IPAex・原ノ味・Noto・ヒラギノ・游 など埋め込まれたもの。欧文: fontenc（OT1/T1）、lmodern・newtx の本文・times・helvet・palatino 系・inconsolata など | 1 | — |
| 数式の書体 | 既定（Computer Modern）・lmodern・mathpazo・mathptmx **だけ** | 1 | — |
| 数式 | amsmath・amssymb（`align*`・`equation`・`\[ \]`・`gather` など） | 2 | 数式（別行立て） |
| 表 | tabular・booktabs・array・tabularx | 3 | 表（tabularx の X 列は左寄せ、幅は持たない） |
| 図 | graphicx・float・caption（`figure`） | 2 | 図＋キャプション |
| 見出し | `\section`〜`\subsubsection`（`*` 付きも）、titlesec・sectsty で見た目を変えたもの、`\paragraph` | 3 | 見出しレベル1〜3（`\paragraph` は後ろの文と同じ行に組まれるので、合わせて段落） |
| 箇条書き | itemize・enumerate・description、enumitem で記号・番号を変えたもの | 3 | 箇条書き（description の見出し語は項目の頭の太字） |
| コード | verbatim・lstlisting（listings）・minted・fancyvrb（色・行番号・枠は可） | 3 | コード（色・行番号・枠は捨てる） |
| 引用 | quote・quotation | 3 | 段落 |
| 文字 | 太字・斜体・下線（ulem）、`\texttt`、色（xcolor）、url・hyperref | 3 | 段落の装飾（色・リンクは捨てる） |
| タイトル・目次 | `\maketitle`、`\tableofcontents` | 2 | タイトル・著者・日付、目次はその他（捨てる） |
| ページ番号・ヘッダー | 既定のもの、fancyhdr | 3 | その他（捨てる） |

### 対象外

**許可リストに無いものは全部対象外。** 特に明記しておくもの:

- TeX 以外で作った PDF（Word・Google ドキュメントなど）。正解を目印で自動で付けられないため
- 文字の層の無い PDF（スキャン）。これは画像読み込みで扱う
- `\chapter` のある文書クラス（report・book・jsbook など）。エディタの見出しはレベル1〜3（`\section`〜`\subsubsection`）なので、章を入れると4段になって表せない
- CM 系以外の数式の書体（newtx の数式・unicode-math など）
- セルの結合（`\multicolumn` / `\multirow`）、longtable
- TikZ・pgfplots、subcaption で並べた図
- 参考文献（thebibliography・BibTeX）、脚注
- 縦書き、3段以上の段組（multicol）、写真

### 留意点

- **数式の書体（決定）:** CM 系（既定・lmodern・mathpazo・mathptmx）に限る。数式OCR（math_ocr）が学習した書体と同じ
  （matplotlib の mathtext と、pdflatex で既定・mathpazo・mathptmx。[math_ocr/render_latex.py](math_ocr/render_latex.py)）。
  math_ocr がほかの書体も学習したら広げる
- **正解の付け方:** TeX で作る限り、目印で自動で付けられる。LuaLaTeX では `\special{pdf:dest}` の代わりに
  `\pdfextension dest` で同じ名前の目印を置く（[hybrid_extractor/real_reports.py](hybrid_extractor/real_reports.py)）。
  TeX 以外で作ったPDFを入れるときだけ、正解を人が付ける（[evaluation/import_dataset.py](evaluation/import_dataset.py)）
- **評価用データの作り方:** 学習データと作り方を変えた評価用データセットを固定しておく。ルールを直すときにも、
  評価用データを見ながら直さない。作り方を知っている側（ルールでもAIでも）が有利にならないようにするため

### 対応状況

| 段階 | 学習データ・評価データ | 抽出器 |
|---|---|---|
| 1 書体 | 未対応（評価用 synth_doc・学習用 doc_gen に書体の切り替えを足す） | 未対応（hybrid_extractor は書体の名前に頼っている） |
| 2 エンジン・文書クラス・組版・数式・図・タイトル | LuaLaTeX の目印は real_reports.py で対応済み。1段/2段組・`align*`・figure・`\maketitle` は対応済み | 2段組・数式・図は対応済み。ほかは未確認 |
| 3 見た目を変えるパッケージ・書き方 | 未対応（real_reports.py で minted・description・quote・`\paragraph`・tabularx・目次の目印は試した） | 未対応 |

## 評価の方法（検討中）

入力は自由だが、出力はエディタの機能の範囲でしか出せない。そのため「入力のPDFとそっくりに戻せたか」では測れない。
**入力を、エディタで表せる形に落としたもの**を正解にして、それと比べる。

### 正解の作り方: 入力をエディタの形に落とす

正解は、文書を作ったときの TeX から、許可リストの「出力での扱い」の決まりで作る（目印の名前に、落とした先の要素を記録する）。
例えば description は箇条書き、quote は段落、色付きのコードはコードの正解にする。
こうすると、エディタに無いものを「戻せなかった」と数えずに済み、エディタにあるものだけで点数が決まる。

捨てるものは2つに分けられる。

| 種類 | 例 | 採点 |
|---|---|---|
| 捨てるのが正しいもの | ページ番号・ヘッダー・目次 | 正解は「その他」。今と同じく、捨てられたかを採点する |
| 何を出しても構わないもの | 今の許可リストには無い（許可リストを広げて、どの要素にも落とせないものを入れるときに使う） | **採点しない範囲**にする。その範囲に重なる予測は、誤検出にも見逃しにも数えない |

採点しない範囲は、今の評価（[evaluation/metrics.py](evaluation/metrics.py)）には無い。要るようになったら、正解の要素に印（例: `label="ignore"`）を付け、
対応付けの前に、その範囲に重なる予測を取り除く。

### 測るもの

| 指標 | 何を見るか | 今の評価 |
|---|---|---|
| ブロックの検出・ラベル・見出しレベル・読み順 | エディタのブロックに正しく分けられたか | ある（f1・label_acc・level_acc・order_acc） |
| 文字・装飾 | ブロックの中の文字と太字・斜体・下線 | ある（cer・deco_f1） |
| 表・数式・コード | セルと揃え、LaTeX、字下げ | ある（table_*・math_ter・code_indent_acc） |
| 文書の設定 | 用紙・文字の大きさ・1段/2段組 | 無い。足すなら IR に文書の設定を持たせる必要がある |
| 往復の確認 | 読み込んだ結果をエディタの TeX にしてコンパイルし直したとき、文字と構造が元と同じか | 無い（見た目は書体などが変わるので比べない） |

### 決めること

- 許可リストの「出力での扱い」を、正解の作り方（synth_doc・doc_gen）に入れる順番（段階に合わせる）
- 文書の設定と往復の確認まで測るか（最終的な評価にどこまで入れるか）
