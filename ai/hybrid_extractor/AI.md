# hybrid_extractor の自作AI — アルゴリズムの説明

ルールのオペレータが聞く「専門家」のうち、3種類を自作AIにした。この文書は、その仕組みを順番に説明する。
コードは [features.py](features.py)（特徴）、[nn.py](nn.py)（モデルと学習）、[train.py](train.py)（学習と比較）、
[ai_experts.py](ai_experts.py)（使うとき）、[operator_rules.py](operator_rules.py) の `predict_ai`（AIモード）。

| 専門家 | 見るもの | 答え | モデル |
|---|---|---|---|
| 区切り | 今のブロックと、次の行 | 次の行は続きか（0〜1） | MLP |
| ラベル（8人） | 1ブロック（と前後のブロック） | 自分のラベルか（0〜1）。段落・箇条書き・コード・見出し・数式・表・キャプション・その他 | MLP（ラベルごとに1つ） |
| 文中の数式 | 段落の文字の並び | 1文字ずつ、数式の文字か（0〜1） | 小さい Transformer |

---

## 1. 全体の流れ

```
PDF ─ 抽出器（ルール）─▶ 行
     ─ 区切りの専門家（AI）: 行を上から順に見て「次の行は今のブロックの続きか？」→ 0.5 以上ならつなぐ ─▶ ブロック
     ─ オペレータ（ルール）:
          表・図の領域 → そのまま
          1ページ目のタイトル部分 → ルール（正解率 1.0 なのでルールのまま）
          それ以外 → ラベルの専門家8人に聞き、一番自信のある答え（誰も 0.5 未満なら段落）
     ─ 文中の数式の専門家（AI）: 段落の中の $...$ の範囲を見つける → 数式を読む係（ルール）で LaTeX に
     ─▶ ラベル付きIR
```

AI は「全部を1つの大きいモデルで」ではなく、**小さい専門家に分けて、オペレータ（ルール）がまとめる**形にしている。
理由: 1人ずつルール版と入れ替えて比べられる、間違えたときにどの専門家のせいか分かる、確実なところ（表・図の領域、タイトル）はルールのまま残せる。

---

## 2. 学習データ（正解をどう作るか）

人がラベルを付けるのではなく、**正解が分かっている文書を TeX で作って PDF にする**（[doc_gen.py](doc_gen.py)）。
各ブロックの始まりと終わりに目印（`\special{pdf:dest}`）を置き、PDF の上での位置を読む（評価サイトと同じ仕組み）。

| データ | 作るコマンド | 1件 | 正解 |
|---|---|---|---|
| 区切り | `build_dataset.py` | 隣り合う2行の組 | 2行が同じ正解のブロックに入っているか（`pairs[].same`） |
| ラベル | `build_dataset.py` | 抽出器のブロック | ブロックの面積の半分以上が重なる正解のブロックのラベル |
| 文中の数式 | `inline_math_data.py` | 段落の1文字 | 文字が `$...$` の目印の間にあるか |

学習用（seed 0 / 10）・検証用（seed 1 / 11）・テスト用（seed 2 / 12）は、**別の乱数の種**で別の文書を作る。
- **学習用**: 重みを直すのに使う
- **検証用**: 「どの時点の重みが一番良いか」を選ぶのに使う（学習を止める時点を決める）
- **テスト用**: 最後に1回だけ成績を測る。学習にも選択にも使っていないので、「見たことの無い文書」での実力になる

文書の見た目はわざとばらつかせている（番号の無い見出し、記号の違う箇条書き、キャプションが下の表…）。
評価用の synth_all のように作りがそろっていると、ルールで満点になり、AI を作る意味が無いため。

## 3. 特徴（features.py）

モデルが読めるのは数字だけなので、ブロックや行を**数字の並び（特徴ベクトル）**にする。
人がルールを書くときに見ている手がかりを、そのまま数字にしたもの、と考えるとよい。

### 大きさをそろえる

長さはすべて**本文の文字サイズで割る**。例: 行の間のすき間 `gap = 0.7` は「本文の文字の 0.7 個分」。
こうすると、10pt の文書でも 12pt の文書でも、A4 でもレターでも、同じ意味の数になる。

### 区切りの専門家の特徴（31個）

| 特徴 | 意味 | なぜ効くか |
|---|---|---|
| gap | 前の行の下端と次の行の上端のすき間 | 段落の中の行は 0.6 くらい、見出しの前後や段落の間はもっと広い |
| dx_prev / dx_first | 前の行・ブロックの1行目との左端のずれ | 字下げ（段落の1行目）、箇条書きの続きの行（1行目より右） |
| prev_short | 前の行が、段の右端より手前で終わっている量 | 段落の最後の行は短い → 次は新しい段落の可能性 |
| prev_indent / next_indent | 段の左端からの字下げ | |
| prev_size / next_size / size_ratio | 文字の大きさと、その比 | 見出しと本文の境目 |
| same_font | 前の行と次の行の書体が同じか | 本文と同じ大きさの太字の見出し（書体だけが違う） |
| same_column / x_overlap | 同じ段か、横に重なっているか | 2段組の、左右の段の行をつながない |
| prev_kind / next_kind / group_kind | 行の種類（文字・数式・コード）と、ブロックの種類（＋箇条書き） | 数式・コードはつなぎ方が違う |
| prev_list_head / next_list_head | 「•」「1.」などで始まるか | 箇条書きの次の項目 |
| prev_end_sentence / prev_end_comma | 前の行が「。」で終わる / 「、」で終わる | 文の途中なら続きの可能性が高い |
| next_tiny / log_next_chars | 次の行が3文字以下 / 文字の数 | 数式の断片（`n`、`i=1`）は短い |

### ラベルの専門家の特徴（52個）

| まとまり | 特徴 |
|---|---|
| 文字 | 本文との大きさの比、太字か、本文と同じ書体か、等幅・数式のフォントの割合 |
| 形 | 位置（x0, y0, x1, y1）、幅、高さ、中央からのずれ、行数、1行目の字下げ、文字数 |
| 先頭 | 数字・英大文字・英小文字・日本語・記号で始まるか、節番号（`1.2 `）、「表1」「Figure 2」、`(a)` `1.` |
| 終わり | 「。」で終わる、「:」で終わる |
| 中身 | 数字・英字・日本語・記号の割合、数字だけか（ページ番号） |
| 場所 | 1ページ目か、ページの上端・下端か、複数ページの上に同じ文字が出るか（ヘッダー） |
| 前後 | 前・次のブロックとのすき間、大きさの比、同じ書体か、等幅か、箇条書きか、**表か・図か** |

「前後」があるのは、1つのブロックだけでは決められないことが多いため。
例: 「図1 枠線だけの図」がキャプションか段落かは、**すぐ隣に図があるか**で決まる。

### 文中の数式の専門家の特徴（1文字あたり27個 ＋ 文字そのもの）

| 特徴 | 意味 |
|---|---|
| フォントの種類 | 数式のフォント（CMMI・CMSY など）、等幅、太字、黒板太字（MSBM）、和文 |
| 文字の種類 | 英小文字・英大文字・数字・日本語・ギリシャ文字・数学記号・演算子・かっこ・句読点・アクセント |
| 大きさ | ブロックの文字サイズとの比、小さいか（添字） |
| ベースラインのずれ | 行のベースラインからのずれ（上付きは負、下付きは正） |
| PyMuPDF の印 | 斜体、太字 |
| 間隔 | 前の文字・次の文字とのすき間 |
| 前後 | 前の文字・次の文字が数式のフォントか |

さらに、**文字そのもの**（`x` `=` `の` など）を ID にして、モデルの中で「埋め込み」（下の 5.）にする。

## 4. MLP（区切りの専門家・ラベルの専門家）

### 形

```
特徴（31 か 52 個）→ 全結合（64個）→ ReLU → ドロップアウト
                  → 全結合（64個）→ ReLU → ドロップアウト
                  → 全結合（1個）= ロジット → sigmoid → 確率（0〜1）
```

- **全結合（Linear）**: `出力 = 重み × 入力 + かたより`。入力の数字を、学習した重みで足し合わせる。64個の出力は、64通りの「足し合わせ方」
- **ReLU**: 負の数を0にする（`max(0, x)`）。これをはさむと、「AかつB」「AだけどBではない」のような、足し算だけでは表せない組み合わせを表せる
- **ドロップアウト**: 学習中だけ、ランダムに 10% の値を0にする。特定の特徴に頼りすぎないようにする（覚えすぎの防止）
- **sigmoid**: どんな数も 0〜1 にする（`1 / (1 + e^(-x))`）。ロジット 0 → 0.5、大きい正の数 → 1 に近い

### 学習（train_binary）

1. **特徴をそろえる（標準化）**: 特徴ごとに `(値 − 平均) ÷ 標準偏差`。「文字数（数百）」と「太字か（0/1）」のように大きさの違う特徴を、同じくらいの大きさにする。平均・標準偏差は**学習用データだけ**から求め、保存しておいて使うときも同じ値で割る
2. **ミニバッチ**: 学習用データを 256 件ずつに分け、1回ずつ次をくり返す
   - 予測（ロジット）を出す
   - **損失**（どれだけ外れているか）を測る: 2値の交差エントロピー。正解が「はい」なのに確率 0.1 と言うと、大きい罰（−log 0.1 ≈ 2.3）
   - **誤差逆伝播**: 損失を小さくするには、各重みをどちらに動かせばよいか（勾配）を計算する
   - **Adam**: 勾配の方向に重みを少し動かす（学習率 0.001）。重みごとに動かす量を自動で調整する方法
3. **「はい」が少ないときの重み（pos_weight）**: 例えば数式のブロックは全体の 6%。全部「いいえ」と答えても正解率 94% になってしまうので、「はい」の見逃しを `いいえの数 ÷ はいの数` 倍重く数える
4. **早期終了**: 1周（エポック）ごとに検証用データの損失を測り、一番小さかったときの重みを残す。6回続けて良くならなければ止める。学習用データの損失は下がり続けても、検証用が上がり始めたら、学習用データを**覚えすぎている**（過学習）

### ラベルの専門家は8人

ラベルごとに「そのラベルか、そうでないか」の MLP を1つずつ学習する（one-vs-rest）。
オペレータは8人の確率を比べて、一番高いラベルを採る。

## 5. 小さい Transformer（文中の数式の専門家）

1文字ずつ「数式か」を当てる問題（**系列ラベリング**）。1文字だけを見ても決められない（`x` は数式の中にも英文の中にもある）ので、
**前後の文字を見比べる**必要がある。それをするのが Transformer の自己注意。

### 形（CharTagger）

```
文字のID ─ 埋め込み（32次元）──────┐
1文字の特徴（27個）─ 全結合（32次元）┴ つなぐ（64次元）＋ 位置の埋め込み（何文字目か）
  → Transformer エンコーダ層 × 2
       自己注意（4つの頭）: 各文字が、ほかの全部の文字を見て、関係の強い文字の情報を集める
       → 全結合 → ReLU → 全結合
  → 全結合（1個）→ sigmoid → 1文字ずつの確率
```

- **埋め込み（Embedding）**: 文字の ID を、学習できる 32 個の数字の並びにする。学習が進むと、似た使われ方の文字（`x` と `y`、`+` と `−`）が近い数字になる
- **位置の埋め込み**: 自己注意そのものは順番を知らないので、「何文字目か」も数字にして足す
- **自己注意**: 例えば `E = mc2` の `=` は、両隣の `E`（数式のフォント）と `m`（数式のフォント）を強く見て、「数式の中の `=`」と判断できる。英文の中の `=` なら、隣は普通の英字
- 学習は MLP と同じ流れ（損失は、埋め草でない文字だけで数える）。長いブロックは 512 文字ずつに区切る

### 範囲にする（spans_from_probs）

確率 0.5 以上の文字が続くところを1つの数式にする。改行では切り、前後の空白は外し、見える文字が無いものは捨てる。

## 7. 試行錯誤から分かったこと

### 段落の専門家は要った

最初は「段落はどの専門家も手を挙げなかったときの答え」にしていた。すると、箇条書きの専門家（pos_weight で見逃しを重く数えるので、手を挙げやすい。適合率 0.78）に段落が負けて、段落の正解率が 0.998 → 0.860 に下がった。
段落にも専門家を作り、8人で自信を比べ合うようにすると、全体 0.959 → 0.979。

### ショートカット学習: 「表1 で始まればキャプション」

サンプルの「表1 は、罫線のある表の例である。」（段落）を、キャプションの専門家が 0.97 でキャプションと言った。
学習データに「表1は…」で始まる段落が1つも無く、AI が「表N で始まればキャプション」という**近道**を覚えていた。
直したのは AI ではなく**データ**: 表・図を参照する文で始まる段落（「表2に示すように…」「Figure 1 compares …」）を作るようにし、
特徴に「前・後のブロックが図か」を足した。学習し直すと、その段落のキャプションの自信は 0.06 になった。
（チームの block_classifier の「ゴシック体なら見出し」と同じ種類の失敗。**学習データに無いものは、AI は知らない**）

### pos_weight と、しきい値

「はい」が少ないときに見逃しを重く数える（pos_weight）と、AI は「はい」と言いやすくなる（確率が高めに出る）。
ラベルの専門家では、段落の専門家を作って比べ合わせることで、文中の数式の専門家では、**しきい値を 0.5 から 0.9 に上げる**ことで直した
（しきい値は検証用データで選ぶ。テスト用データ・比較実験で選ぶと、答えを見ながら調整したことになる）。

### 1文字ずつ良くても、まとまりで負けることがある

文中の数式の専門家は、1文字ずつの F1 ではルールより良かった（0.954 → 0.961）のに、数式のまとまりの F1 では負けた（0.872 → 0.824）。
数式の中の空白の確率が低く、`r = 1` が `r`・`=`・`1` の3つに割れていた。1文字の間違いで、1つの正解が見逃しになり、かけらが3つの誤検出になる。
「間が空白・演算子・かっこだけ（改行以外）ならつなぐ」「前の関数名を入れる」という**ルールの後処理**を足して 0.888。
（調整用のスクリプトにはこの後処理が入っていたのに、実際の専門家には入れていなかったので、一度は比較実験で 0.767 まで下がった。
**調整したときと、実際に使うときを、同じ処理にそろえる**）

### 点数が急に下がったら、まずエラーを見る

AI を評価サイトにかけたら再現率が 0.920 → 0.837 に下がった。AI が悪いのではなく、数式を読む係の不具合
（下ごしらえでまとめた何文字もある1文字のせいで、式番号を探す位置がずれた）で、10文書が丸ごと0点になっていた。
直すと検出 F1 は 0.990。

### AI が見つけたぶん、後ろのルールの弱点が見えた

AI が新しく見つけた難しいブロックで、後ろのルールの処理が外れていた:
等幅の書体 `txtt`（newtx の \ttfamily）を等幅と判定できず、コードの字下げが付かない（→ 書体の名前を足し、ラベルがコードなら字下げを戻す・行番号を除く）、
番号の無い見出しのレベルを文書の中の大きさの順位で決めていた（→ 本文との大きさの比で決める）。
直すと、ルール版のコードの正解率も 0.528 → 0.828 に上がった。

## 7.5 書体を自由にして学習し直した（2026-11-16）

PDF読み込みの許可リストの段階1（[../CONSTRAINTS.md](../CONSTRAINTS.md)）で、学習データ（doc_gen.py）に書体を混ぜ、3人の専門家を学習し直した。
抽出器の側の変更（等幅を送り幅で決める、数式の文字の印など）は [README.md](README.md) の「書体を自由にする」。

| 専門家（テスト用データ。書体を混ぜた、学習と別の seed） | ルール版 | AI版 |
|---|---|---|
| 区切り（2行の組 8,583、正解率） | 0.934 | **0.987** |
| ラベル（オペレータで決めた正解率） | 0.834 | **0.981** |
| 文中の数式（1文字ずつの F1） | **0.955** | 0.952 |
| 文中の数式（比較実験、見つける F1、1,291個） | 0.891 | **0.908** |

評価サイトの簡易の物差し（hybrid_fonts、書体を混ぜた60文書）: AI の検出F1 0.970 → **0.981**、ラベル 0.976 → **0.985**。
どの書体でもラベル正解率は 0.97〜0.99（直す前に一番低かった mathptmx も 0.957 → 0.979）。

### 分かったこと

- **特徴の意味を変えたら、学習し直す。** 1文字の特徴「数式のフォントか」を「数式の文字の印（書体の名前＋短い斜体の並び）」に変え、
  ブロックの `math_ratio` に数式の記号も数えるようにした。前の重みのままだと、学習のときと違う意味の数が入ってしまう
- **正解が特徴に漏れないように、名前をぶつけない。** 文字の印を最初 `ch["math"]` という名前にしかけたが、文中の数式の学習データ（inline_math_data.py）は
  `"math"` を**正解**（その文字が数式か）に使っていた。そのままだと `is_math()` が正解を読んでしまい、テストの点数だけが不自然に良くなる。
  印は `math_char` / `mono_char` / `math_like_char` にした
- **ルールが良くなると、AI の伸びしろは減る。** 文中の数式は、ルール版も印のおかげで書体に強くなり、1文字ずつの F1 は AI とほぼ並んだ
  （まとまりで見ると AI がまだ上。後処理の「間が空白・演算子ならつなぐ」が効いている）
- **データの作り方の不具合は、AI の点数だけを見ても気づけない。** newtxtext の文書では PDF から図が消えていて、キャプションだけが残っていた。
  ルールの「キャプションなのに段落」を1つずつ見ていて、ようやく気づいた

## 7.6 蒸留を試した（文中の数式の専門家、2026-11-25）

**知識の蒸留**（Hinton ら 2015）: 強いモデル（先生）が出す確率を、正解（0か1）と一緒に学習の目標にして、小さいモデル（生徒）を学習する。
先生の確率には「どれくらい迷ったか」が入っている（英文に紛れた x は 0.6、f(x) の x は 0.95）。正解の 0/1 には無い情報なので、生徒が学びやすくなる。

- **先生:** 今と同じ形の Transformer を、乱数の種だけ変えて3つ（種0 = 今の inline_math.pt、種1・種2）。3つのロジットの平均（アンサンブル）を先生の答えにする。
  大きい先生は CPU だと一晩かかるので、同じ大きさを3つにした（1つ1時間）
- **生徒:** 同じ形（2層・幅64）、種3。速さは今の専門家と同じ
- **損失:** `α × 正解との損失 + (1 − α) × 先生との損失`（α = 0.5）。先生との損失は、先生と生徒のロジットを温度 T（= 2）で割ってからの交差エントロピーに T² を掛けたもの（`nn.distill_loss`）。
  T で割ると 0.98 のような自信過剰な確率がなだらかになり、迷い具合が伝わる。T² は、割ったぶん小さくなった勾配を戻すため。パラメータの更新は1回（2つの損失を足してから逆伝播）。先生は更新しない（ロジットは学習の前に1回だけ計算）
- **しきい値:** 生徒の確率はなだらかになるので、検証用データで数式のまとまりの F1 が一番良いしきい値を選び直し、重みと一緒に保存する（生徒は 0.95）

| テスト用データ（inline_test、120文書） | 1文字ずつの F1 | まとまりの F1 |
|---|---|---|
| ルール版 | 0.9551 | |
| 先生 種0 / 種1 / 種2 | 0.9521 / 0.9507 / 0.9458 | 0.9504 / 0.9538 / 0.9498 |
| 先生3人の平均（アンサンブル。3倍遅い） | **0.9593** | **0.9544** |
| **生徒（蒸留）** | 0.9560 | 0.9538 |

比較実験（inline_math_eval、別に作った60文書・1,291個）: 見つける F1 ルール 0.891、先生 種0 0.908、**生徒 0.912**。

- 1文字ずつでは、生徒は先生1人ずつのどれよりも良く、ルール版もわずかに超えた。先生1人の平均（0.9495）からアンサンブル（0.9593）への伸びの、約3分の2を1人分の速さで取り戻した
- まとまりでは、生徒は一番良い先生と同じくらい。先生どうしの差（種だけで 0.004）と同じくらいなので、「まとまりでも効いた」とは言い切れない
- 速さは変わらない（形が同じ）。使うときは `--inline-checkpoint inline_student.pt`（比較実験）、または inline_math.pt と入れ替える

```bash
python -m hybrid_extractor.train inline --epochs 10 --seed 1 --out inline_teacher_s1.pt   # 先生（種0 は inline_math.pt）
python -m hybrid_extractor.train inline --epochs 10 --seed 2 --out inline_teacher_s2.pt
python -m hybrid_extractor.train distill --teachers inline_math.pt inline_teacher_s1.pt inline_teacher_s2.pt \
    --temperature 2 --alpha 0.5 --seed 3 --out inline_student.pt                          # 生徒（約1時間）
python -m hybrid_extractor.inline_math_eval --out hybrid_extractor/data/inline_math --docs 60 --finder ai \
    --inline-checkpoint inline_student.pt
```

## 7.7 見たことのない見た目・中身への強さ（2026-11-25）

学習データと評価データを同じ作り方（doc_gen.py）で作ると、AI が作り方を覚えたぶん点数が高めに出る。そこで2つを試した
（`generalization.py`、実行の全体は data/gen_run.sh）。

- **見た目:** 学習データから1つの見た目を抜いて学習し（`build_dataset --exclude`、`train --data-prefix --checkpoints`）、抜いた見た目だけの文書で、
  全部で学習した AI と比べる（同じデータ。評価サイトの形、60文書、種4）
- **中身:** 学習に使っていない材料のパック（content.py）の文書で測る。alt = 手で用意した別の単語・見出し・数式の部品・コード、
  real = alt に本物の文（青空文庫の寺田寅彦 871文、Gutenberg のファラデー 778文）と本物の数式（im2latex-100k の文中 243・別行立て 523）

### 見た目（全部で学習した AI → 抜いて学習した AI）

| 抜いた見た目（評価はそれだけの文書） | 検出F1 | ラベル正解率 | 箇条書き F1 |
|---|---|---|---|
| Times の仲間（times・newtxtext・mathptmx） | 0.981 → 0.982 | 0.986 → 0.985 | 0.87 → 0.86 |
| bxjsarticle | 0.978 → 0.976 | 0.984 → 0.983 | 0.85 → 0.84 |
| 箇条書きの記号（★・―・▷） | 0.979 → 0.975 | 0.988 → 0.991 | **0.88 → 0.82** |

文中の数式（Times の仲間だけ、見つける F1）: 全部で学習 0.899 → 抜いて学習 0.906（ルール 0.885）。

- 書体と文書クラスは、見たことがなくても落ちない。書体の名前ではなく送り幅・ベースライン・斜体の並びの長さ（7.5）を手がかりにしているため
- 箇条書きの記号だけは落ちる。AI は「どの記号なら項目の頭か」を記号そのもので覚えていた

### 中身（同じ見た目の分布で、材料だけ変える）

| データ | ルール 検出F1 / ラベル | AI 検出F1 / ラベル |
|---|---|---|
| hybrid_fonts（学習と同じ材料） | 0.907 / 0.911 | **0.981 / 0.985** |
| gen_alt（別の単語・見出し・数式の部品・コード） | 0.880 / 0.906 | **0.958 / 0.970** |
| gen_real（本物の文と数式） | 0.825 / 0.930 | **0.939 / 0.964** |
| gen_only_times_real（Times の仲間 ＋ 本物） | 0.831 / 0.933 | **0.946 / 0.960** |

ラベル別 F1（AI、同じ材料 → real）: 段落 0.94 → 0.82、箇条書き 0.85 → 0.68、数式 0.97 → 0.89。見出し・キャプション・その他は 0.99 のまま。

文中の数式（見つける F1）: 学習と同じ作りの数式 ルール 0.891・AI 0.908 → 本物の数式 ルール **0.760**・AI **0.807**。

- **中身の変化の方が、見た目の変化より効く。** AI は検出F1 が 2〜4 ポイント、ラベルが 1.5〜2 ポイント下がる。AI はやはり材料（言い回し・文の長さ・数式の形）をある程度覚えていた
- それでも、どのデータでも AI がルールより上。ただし、ラベルの差はかなり縮む（同じ材料 0.074 → 本物 0.034）
- ルールのラベル正解率は本物の文でむしろ上がった（0.911 → 0.930）。ルールは言い回しを見ないので、材料を変えても下がらない
- 本物の数式（論文の数式は長く、添字や \left \right が多い）は、ルールも AI も大きく下がる。数式の部品を増やすか、本物の数式の一部を学習に入れる必要がある
- 60文書ずつなので、0.005 くらいの差はぶれの範囲

### 次にやること（案）

1. 箇条書きの頭の手がかりを、記号そのものではなく「行頭の短い記号＋空白が、そろった位置で繰り返す」形にする
2. 学習の材料を増やす（単語・見出し・数式の部品）。ただし評価用に、学習に使わない材料（本物の文・数式の一部）を必ず残す
3. 本物の数式を、学習用と評価用に分けて、学習用の分を文中の数式の専門家の学習に足す
